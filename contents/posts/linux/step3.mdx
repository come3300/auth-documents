# ファイルとディレクトリ

## ファイルとは

コンピューターで実行されるプログラム本体や関連ファイルが保存されている場所です。

**日常生活の例え：本や書類**

ファイルは、本棚に並んでいる「本」や「書類」のようなものです。
- レポート（Word文書）= テキストファイル
- 写真アルバム（画像）= 画像ファイル
- 音楽CD（音声）= 音声ファイル

それぞれ種類が違い、開き方も異なりますよね。

### ファイルの種類

ファイルは大きく分けて2種類に分類できます。

#### テキストファイル

テキスト（文字）が入力されたファイルです。

**特徴：**
- テキストエディタで開いて読める
- 人間が読んで理解できる
- 編集が簡単

**具体例：**
- プログラムファイル（`.js` `.py` `.html`）
- 設定ファイル（`.ini` `.yml` `.config`）
- 文書ファイル（`.txt` `.md`）
- CSVファイル（`.csv`）

**テキストファイルの中身の例：**
```javascript
// sample.js
function hello() {
    console.log("Hello World!");
}
```
→ 開くと、このように人間が読める形で表示されます。

#### バイナリファイル

プログラムやその他のデータを含むファイルです。テキストエディタでは閲覧や編集はできません。

**特徴：**
- 専用のソフトでしか開けない
- テキストエディタで開くと文字化けする
- 人間が直接読めない（0と1の羅列）

**具体例：**
- 画像ファイル（`.jpg` `.png` `.gif`）
- 音声ファイル（`.mp3` `.wav`）
- 動画ファイル（`.mp4` `.avi`）
- PDFファイル（`.pdf`）
- 実行ファイル（`.exe` `.app`）

**バイナリファイルをテキストエディタで開くと：**
```
��JFIF��C�� C��"��
```
→ 文字化けして読めません。

### ファイルとディレクトリの違い

| 項目 | ファイル | ディレクトリ |
|-----|---------|------------|
| 役割 | データを保存 | ファイルを整理 |
| 例え | 本、書類 | 本棚、引き出し |
| 中身 | 文字、画像、音声など | ファイルや他のディレクトリ |

---

## ディレクトリとは

コンピューター上でファイルを整理・分類するための入れ物です。Windowsではエクスプローラー、MacOSではFinderによって確認することができます。

**日常生活の例え：本棚や引き出し**

ディレクトリは「本棚」や「引き出し」のようなものです。

**整理されていない部屋（ディレクトリなし）：**
```
部屋の床に全部散らばっている
├── 写真1.jpg
├── レポート.docx
├── 音楽.mp3
├── 写真2.jpg
├── プログラム.js
└── ...（探すのが大変！）
```

**整理された部屋（ディレクトリあり）：**
```
部屋
├── 写真棚/
│   ├── 写真1.jpg
│   └── 写真2.jpg
├── 書類棚/
│   └── レポート.docx
├── 音楽棚/
│   └── 音楽.mp3
└── プログラム棚/
    └── プログラム.js
```
→ 探しやすい！

<Note>
**ディレクトリの別名**

ディレクトリは「フォルダ」とも呼びます。この講座ではディレクトリと名称を統一します。

- ディレクトリ = 技術用語（Linuxでよく使う）
- フォルダ = 日常用語（Windows、Macでよく使う）

意味は同じです。
</Note>

# ディレクトリ構成

ディレクトリはツリー構造(階層構造)で構成されています。一番上のディレクトリ（ルートディレクトリ）からツリー構造に増えていくようになっています。

**ツリー構造のイメージ：**

```
/（ルートディレクトリ）
├── home/
│   ├── user1/
│   │   ├── Documents/
│   │   │   ├── report.txt
│   │   │   └── memo.txt
│   │   ├── Pictures/
│   │   │   ├── photo1.jpg
│   │   │   └── photo2.jpg
│   │   └── Downloads/
│   └── user2/
│       └── Documents/
├── etc/
│   ├── config.conf
│   └── hosts
└── var/
    └── log/
        └── system.log
```

**日常生活の例え：家系図や組織図**

家系図を想像してください：
- 一番上：祖先（ルートディレクトリ）
- その下：親、子、孫...（サブディレクトリ）
- 枝分かれしながら広がっていく

**図解：**
```
        [/（ルート）]
            │
    ┌───────┼───────┐
    │       │       │
  [home]  [etc]   [var]
    │
  ┌─┴─┐
  │   │
[user1] [user2]
  │
┌─┼─┐
│ │ │
Documents Pictures Downloads
```

この構造により：
- ファイルを分類して整理できる
- 同じ名前のファイルを別の場所に保存できる
- 階層ごとにアクセス権限を設定できる

# ディレクトリの種類

ディレクトリには様々な種類があります。それぞれのディレクトリの役割と意味について解説をしていきます。

## ルートディレクトリ

PC内のディレクトリやプロジェクト、リポジトリごとの**一番上に存在しているディレクトリ**です。

**記号：** `/`（スラッシュ）

**イメージ：**
```
/（← これがルートディレクトリ）
├── home/
├── etc/
├── var/
└── usr/
```

**日常生活の例え：木の根っこ**

「ルート（root）」は英語で「根っこ」という意味です。
木の根っこから幹、枝、葉っぱと広がっていくように、
ルートディレクトリからすべてのディレクトリが広がっていきます。

**重要ポイント：**
- すべてのファイルとディレクトリは、このルートディレクトリの下にある
- Windowsの「C:\」に相当する
- Linuxでは必ず `/` から始まる

## ホームディレクトリ

ターミナルやコマンドプロンプトといったCLIを起動したときに最初に表示されているディレクトリです。

**記号：** `~`（チルダ）または `/home/ユーザー名`

<Note>
**CLIとは**

**ターミナルやコマンドプロンプトなどを総称して「CLI（コマンドラインインターフェース）」** と呼びます。
CUI（キャラクターユーザーインターフェース）とも言います。
</Note>

**イメージ：**
```
/home/
├── tarou/（← tarouさんのホームディレクトリ）
│   ├── Documents/
│   ├── Downloads/
│   ├── Pictures/
│   └── Desktop/
├── hanako/（← hanakoさんのホームディレクトリ）
│   ├── Documents/
│   └── Music/
└── jiro/
    └── Videos/
```

**日常生活の例え：自分の部屋**

アパートを想像してください：
- アパート全体 = PC（ルートディレクトリ）
- 各部屋 = ホームディレクトリ
- 部屋の住人 = ユーザー

tarouさんの部屋（ホームディレクトリ）は、tarouさん専用です。
他の人は基本的に入れません（アクセス権限）。

**ターミナルでの確認方法：**
```bash
# ホームディレクトリの場所を確認
$ echo $HOME
/home/tarou

# チルダはホームディレクトリを表す
$ cd ~
$ pwd
/home/tarou
```

## カレントディレクトリ

今、自分がいるフォルダ（作業中の場所） のことです。

**記号：** `.`（ドット）

**イメージ：**
```
/home/tarou/（← ここにいる場合、ここがカレントディレクトリ）
├── Documents/
│   └── report.txt
└── Pictures/
    └── photo.jpg
```

**日常生活の例え：今いる部屋**

大きな家の中を移動している場面を想像してください：
- 最初：リビングにいる（カレントディレクトリ = リビング）
- 移動後：キッチンにいる（カレントディレクトリ = キッチン）
- 移動後：寝室にいる（カレントディレクトリ = 寝室）

**ターミナルでの確認方法：**
```bash
# 現在のカレントディレクトリを表示
$ pwd
/home/tarou/Documents

# カレントディレクトリ内のファイル一覧
$ ls
report.txt  memo.txt  project/
```

**カレントディレクトリの重要性：**
- コマンドは「カレントディレクトリ」を基準に実行される
- ファイルを操作するときは、カレントディレクトリに注意

**具体例：**
```bash
# カレントディレクトリが /home/tarou の場合
$ ls
Documents  Pictures  Downloads

# Documentsに移動
$ cd Documents

# カレントディレクトリが変わった
$ pwd
/home/tarou/Documents
```

## 主要なディレクトリ

ホームディレクトリやルートディレクトリ以外にも、よく出てくる代表的なディレクトリを紹介します。

Linuxシステムでは、ディレクトリごとに役割が決まっています。

| ディレクトリ | 役割 | 具体例 |
| --- | --- | --- |
| **bin** | バイナリ形式の実行ファイルやコマンドが保管されています。 | `ls`, `cp`, `cat`などの基本コマンド |
| **dev** | デバイス関係のファイルが保管されています。 | ハードディスク、USB、プリンタなど |
| **etc** | 各種設定ファイルなどさまざまなファイルが保管される場所です。 | システムの設定ファイル、アプリの設定 |
| **root** | ルートディレクトリとは別に用意された、システム管理者用のホームディレクトリです。 | rootユーザー（管理者）専用の領域 |
| **sbin** | 管理者用のシステム標準コマンドが保管されています。 | `shutdown`, `reboot`など |
| **usr** | 各ユーザーのデータやアプリケーションが保管される場所です。 | インストールしたソフトウェア |
| **home** | この下にユーザーごとのディレクトリが作られ、そこが各ユーザーのホームディレクトリになります。 | `/home/tarou`, `/home/hanako` |
| **var** | アプリケーションの記録（ログ）ファイルやメールデータなどが保管される場所です。 | ログファイル、キャッシュ |
| **tmp** | 一時ファイルが保存される場所です。 | 再起動すると削除されることが多い |

**視覚的に見るとこんな感じ：**

```
/（ルート）
├── bin/        ← 基本コマンド（誰でも使える）
├── sbin/       ← 管理者用コマンド
├── etc/        ← 設定ファイル
├── home/       ← ユーザーのホームディレクトリ
│   ├── tarou/
│   └── hanako/
├── root/       ← 管理者専用
├── var/        ← ログやデータ
│   └── log/
├── tmp/        ← 一時ファイル
├── usr/        ← ソフトウェア
└── dev/        ← デバイス
```

**日常生活の例え：会社のオフィス**

- `/bin` = 共有の文房具棚（誰でも使える）
- `/etc` = 会社のルールブック（設定）
- `/home` = 各社員のデスク
- `/root` = 社長室（管理者専用）
- `/var/log` = 業務日報（ログ）
- `/tmp` = ゴミ箱（一時保存）

**重要ポイント：**
> これらのディレクトリは、むやみに変更してはいけません。
> 特に `/etc` や `/bin` を間違って削除すると、システムが動かなくなります。
>
> 普段の作業は、自分のホームディレクトリ（`/home/ユーザー名`）で行いましょう。

## まとめ

この章で学んだこと：

1. **ファイル** = データを保存する単位
   - テキストファイル：人間が読める
   - バイナリファイル：専用ソフトで開く

2. **ディレクトリ** = ファイルを整理する入れ物（フォルダ）

3. **ツリー構造** = ルートから枝分かれして広がる階層構造

4. **重要なディレクトリ**
   - `/`：ルートディレクトリ（一番上）
   - `~`：ホームディレクトリ（自分の領域）
   - `.`：カレントディレクトリ（今いる場所）

次の章では、これらのディレクトリ間を移動する「パス」について学びます！
