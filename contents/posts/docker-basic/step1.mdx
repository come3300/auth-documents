## Dockerとは

![Docker Logo](/images/documents/docker-basic/docker-logo.png)

Dockerとは、アプリケーションを「コンテナ」という単位でパッケージ化し、どんな環境でも同じように動かすことができる技術です。
これにより、「自分のパソコンでは動くのに、他の人のパソコンでは動かない」という問題を解決できます。

## 仮想環境

![Virtual Environment](/images/documents/docker-basic/virtual-environment.png)

仮想環境とは、1台のコンピュータの中に、別のコンピュータがあるかのように動作させる技術のことです。


### Dockerと仮想環境の関係

従来の仮想環境（仮想マシン）は、OS全体を丸ごとコピーするため、重くて起動に時間がかかります。
一方、Dockerのコンテナは必要な部分だけを持つ軽量な仮想環境です。

**違いのイメージ：**

- 仮想マシン = 家を丸ごと建てる（重い、時間がかかる）
- Dockerコンテナ = テントを設置する（軽い、すぐに始められる）

Dockerは仮想マシンよりも軽量で高速に起動できるため、開発現場で広く使われています。

## Dockerを使うメリット

### 1. 環境の違いによる問題を解決

**メリット：どこでも同じように動く**

「自分のパソコンでは動くのに、本番サーバーでは動かない」という経験はありませんか？
これは環境の違いが原因です。Dockerを使えば、開発環境も本番環境も同じコンテナで動かせるため、この問題が起きません。

**例え：レシピ通りに作る料理**
- レシピ（Dockerfile）があれば、誰が作っても同じ料理ができる
- 材料や調理器具もすべてセットになっている
- 場所や人が変わっても同じ味を再現できる

### 2. 環境構築が簡単

**メリット：セットアップ時間の大幅短縮**

従来は新しいメンバーが参加するたびに、数時間〜数日かけて開発環境を構築していました。
Dockerを使えば、コマンド1つで数分で環境が整います。

** Dockerなし**
1. プログラミング言語をインストール
2. データベースをインストール
3. 各種ライブラリをインストール
4. 設定ファイルを調整
5. エラーが出たら調査して修正...（数時間〜数日）

** Dockerあり**
1. `docker-compose up` を実行（数分）
2. 完了！

### 3. チーム開発の効率化

**メリット：全員が同じ環境で開発できる**

チームメンバーそれぞれが異なるOS（Windows、Mac、Linux）を使っていても、
Dockerを使えば全員が同じ環境で開発できます。

「Aさんのパソコンでは動くのに、Bさんのパソコンでは動かない」という問題がなくなります。

### 4. クリーンな環境を保てる

**メリット：自身のPCが汚れない**

新しい技術を試すために色々なソフトウェアをインストールすると、パソコンが重くなったり、
バージョンの競合が起きたりします。

Dockerを使えば、コンテナの中だけで試せるため、パソコン本体はクリーンなまま保てます。
不要になったらコンテナを削除するだけでOKです。

## Dockerの概念

Dockerを理解するために、重要な3つの概念を解説します。
これらを理解すれば、Dockerの仕組みが見えてきます。

### コンテナ

![Container](/images/documents/docker-basic/container.png)

コンテナとは、アプリケーションを動かすための独立した実行環境のことです。

**日常生活の例え：コンテナ船の貨物コンテナ**

港にあるコンテナ船を想像してください。たくさんのコンテナ（箱）が積まれていますよね。

- 各コンテナは独立している（中身が混ざらない）
- 標準化されているのでどこでも運べる
- 必要なものがすべて入っている（自己完結）
- 使い終わったら捨てられる（削除が簡単）

**プログラミングでの具体例：**
```bash
# コンテナを起動（アプリを実行）
docker run -d nginx

# コンテナを停止
docker stop コンテナID

# コンテナを削除
docker rm コンテナID
```

### イメージ

![Image](/images/documents/docker-basic/image.png)

イメージとは、コンテナを作るための「設計図」や「型」のことです。

**特徴：**
- イメージは読み取り専用（変更できない）
- Docker Hubなどから取得できる（公式イメージがたくさんある）
- 自分でカスタマイズしたイメージも作れる

**具体例：**
```bash
# Docker HubからNginxのイメージを取得
docker pull nginx

# イメージ一覧を表示
docker images

# イメージからコンテナを起動
docker run nginx
```

### ボリューム

![Volume](/images/documents/docker-basic/volume.png)

ボリュームとは、コンテナのデータを永続的に保存するための仕組みです。

**日常生活の例え：外付けハードディスク**

ノートパソコンと外付けハードディスクを想像してください。

- コンテナ = ノートパソコン（買い替えることができる）
- ボリューム = 外付けハードディスク（データを永続保存）
- パソコンを買い替えても、外付けHDDのデータは残る = コンテナを削除しても、ボリュームのデータは残る

**なぜ必要？**

コンテナは「使い捨て」が基本です。コンテナを削除すると、中のデータも消えてしまいます。
しかし、データベースのデータなど、消えては困るデータもあります。

そこで、ボリュームを使ってコンテナの外にデータを保存します。

**具体例：**
```bash
# ボリュームを作成
docker volume create my-data

# ボリュームをマウントしてコンテナを起動
docker run -v my-data:/var/lib/mysql mysql

# コンテナを削除してもmy-dataボリュームは残る
```

**重要なポイント：**
- コンテナは削除してもボリュームは残る
- 複数のコンテナで同じボリュームを共有できる
- バックアップやデータ移行が簡単
